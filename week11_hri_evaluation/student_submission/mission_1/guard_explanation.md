a REQUEST guard is only allowed to start or replace a task in IDLE, CLARIFY, CONFIRM, RECOVERY or CANCELLED. Once the robot is moving, changing the goal needs an explicit CORRECT, which clears the old confirmation. In the "Active task needs an explicit correction" trace, row 4 is a REQUEST that arrives while the phase is EXECUTING. decide() returns hold, so the phase stays EXECUTING and nothing is delivered. Without this guard, a stray or misheard request during the trip would silently switch the robot's target without the person confirming the new cup.
