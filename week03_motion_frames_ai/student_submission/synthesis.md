# Technical synthesis

A robot motion program can be technically correct yet fail sociotechnically. For example, a delivery robot in a hospital corridor may execute its alternating arcs perfectly, but if it does not signal intent or yield, it can startle or block nurses, patients, or wheelchair users. The code passes all geometric and velocity tests, yet the robot disrupts shared-space norms. To evaluate this, we need additional evidence: observations of human-robot encounters, interviews with staff about predictability and accessibility, and compliance checks against shared-space rules. We also need to know whether the robot’s behavior matches pedestrian expectations—does it slow down, signal turns, or make its path legible? Technical metrics alone cannot capture whether the robot is socially acceptable or safe in practice. Sociotechnical evaluation therefore requires human-centered data, not just parameter checks.
